## Purpose

Demonstrate a read-only IAM control and report generation using **fabricated data only**. This is a sample analytical workflow; the output does not certify authorization, compliance, termination completion, or remediation.

## Requirements

- PowerShell 7.2 or later (`pwsh --version`)
- Git (to clone) or GitHub's **Code → Download ZIP** menu
- No AD domain, credentials, privileged rights, or vendor integration required for this demo

## Run

1. Download or clone [the project](https://github.com/norones-rgb/service-account-hygiene-auditor).
2. Open a PowerShell terminal in the repository root.
3. Run the exact synthetic command:

```powershell
./Invoke-ServiceAccountHygieneAudit.ps1 -Mode Demo -AsOfUtc '2026-11-05T19:00:00Z'
```

4. Open the generated **HTML** report from `output/`. Inspect the accompanying **CSV** and **JSON** artifacts. Output file/folder names vary by project; see `README.md` for the naming convention.
5. Compare the report to the pinned fixture expectation below. Review the findings and the cases that deliberately represent evidence gaps.

## Expected sample

- Mode: Offline synthetic snapshot mode (no AD connection)
- Inputs: `sample-data/service-accounts.synthetic.json`
- Fixture baseline: **11 synthetic accounts, 20 findings (2 critical, 9 high, 3 medium, 5 low, 1 informational)**
- Static screenshot-style preview: [docs/fixture-preview.html](docs/fixture-preview.html)

A preview is explanatory example output; the report generated by the command is the authoritative demo artifact for that code version.

## Run the automated checks locally

```powershell
Install-Module Pester -MinimumVersion 5.5.0 -Scope CurrentUser -Force
Import-Module Pester -MinimumVersion 5.5.0
Invoke-Pester -Path ./tests -CI -Output Detailed
```

Check [GitHub Actions](https://github.com/norones-rgb/service-account-hygiene-auditor/actions/workflows/ci.yml) for Windows and Linux runs. Passing automated tests do not replace an authorized pilot with representative directory and application data.

## Security and evidence interpretation

- **Never** insert real user records, tokens, credentials, or customer exports into a public repository or issue.
- An absent identity or missing entitlement from an **incomplete** export must not be interpreted as proof that access was removed.
- Findings are prompts for human investigation; changes to access and review decisions remain outside the analyzer.
- For real pilots, use an approved environment, limited read-only permissions, a documented scope, and restricted report storage.
- Review the project's `SECURITY.md` or `docs/security-and-privacy.md` and `NOTICE` before reuse.
